# 运行手册

## 一、日常启动

```
双击 start.bat
```

首次运行会自动建运行环境、装依赖、起服务、开浏览器。
**关掉那个命令行窗口 = 停止服务。**

访问地址固定是 `http://127.0.0.1:8731`。令牌会随启动打印在窗口里，浏览器会自动带上。

### 启动脚本长什么样

`start.bat` 只是个二十来行的纯 ASCII 骨架，真正的流程在 `scripts\bootstrap.py`：

```
[1/4] 运行环境     .venv 不在就建
[2/4] 中台依赖     pip install -r backend\requirements.txt
[3/4] 模块环境     每个模块自己的 .venv（见 docs\MODULES.md）
[4/4] 启动中台     先探端口，再起服务并打开浏览器
```

也可以直接调它，参数比经 bat 透传清楚：

```bash
.venv\Scripts\python.exe scripts\bootstrap.py                  # 完整流程
.venv\Scripts\python.exe scripts\bootstrap.py --modules-only   # 只准备环境，不起服务
.venv\Scripts\python.exe scripts\bootstrap.py --only opsgen    # 只处理某个模块
.venv\Scripts\python.exe scripts\bootstrap.py --force          # 连已建好的也重建
```

> ⚠️ **改 `start.bat` 之前先读这条。** 这个文件必须保持**纯 ASCII、CRLF 行尾、
> 不带括号块**。cmd.exe 解码 bat 用的是控制台代码页，UTF-8 中文 + LF 行尾会让它
> 算错行偏移、把注释里的词当成命令去执行 —— 实测报出过 `'newer:'`、`'Then'`、
> `'See'` 不是内部或外部命令，而报错位置和真正出问题的行毫无关系，看报错根本
> 无从下手。
>
> **要加提示，就加进 `bootstrap.py`**（那边中文正常，而且逻辑可测）。同理，代码页
> 由 Python 自己设（`SetConsoleOutputCP`），不靠 bat 里的 `chcp` —— chcp 之后 cmd
> 重读批处理文件时同样可能算错偏移，那正是要躲开的坑。

## 三、单独启动某个模块（只在排障时用）

### 模块二：OpsGen（运维脚本生成）

中台在管它的生命周期，正常路径就是在「模块」标签页操作（打开 / 重启 / 看日志）。
下面这些只在你想绕开中台、直接验证模块本身时才用：

```bash
cd modules\opsgen
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

> ⚠️ **不要用 `python app.py`，也不要为了"安全"去改它。**
> `app.py` 最后一行是 `socketio.run(app, host="0.0.0.0", port=port, debug=True, ...)`：
> - `host="0.0.0.0"` → 服务开到局域网，同网段的人都能访问你的机器
> - `debug=True` → 报错页会暴露源码片段
>
> 直接 `python app.py` 就会踩中这两条。中台的做法是**不改上游源码**，而是用一个
> 启动壳只 `import` 它的 `app` 对象、绕开它的 `__main__` 分支，把监听地址钉死在
> `127.0.0.1` —— 那两行危险的默认值于是根本没机会生效。自检脚本里有一条断言
> 专门盯着这件事：那句 `host="0.0.0.0"` **必须还留在原文件里**。
>
> 手改上游源码会让日后 `git pull` 同步上游冲突不断，所以别改。

### 模块三：工作地址集合门户

```bash
cd modules\portal\backend
..\..\..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

然后浏览器打开 `http://127.0.0.1:8000`。

需要 `modules/portal/.env` 存在且 `SECRET_KEY` 已设置。**请自行确认它不是样例里的默认值**
（`please-change-this-secret-key`）——默认值意味着任何知道它的人都能伪造登录态。
生成方式：`openssl rand -hex 32`。

前端产物在 `modules/portal/frontend/dist/`，中台直接托管它，**平时不需要碰前端**。
只有改了 `frontend/src/` 里的源码才需要重新构建：

```bash
cd modules\portal\frontend
npm install        # node_modules 不进版本库，换机器要装一次
npm run build
```

> ⚠️ **改了前端源码一定要重新 `npm run build`，否则中台托管的还是旧产物。**
> 这个坑很隐蔽：源码里改了逻辑，浏览器里却毫无变化，很容易怀疑到中台身上。
> 自检脚本里有一条断言专门盯它 —— 它会从构建产物里找
> `__LOCALDECK__`（前端用它算路由 basename），找不到就报"停在旧构建上"。<br>
> 顺带说明 basename 为什么必须存在：前端用 `BrowserRouter`（history 路由），
> 地址栏是 `/portal/admin` 时，react-router 会拿 `/portal/admin` 去匹配
> `/admin` 这条路由 —— 匹配不上，页面直接空白。

## 五、备份与恢复

### 备份

要备份的东西分散在几处：

```
data\                     中台主库、令牌、机器标识
modules\portal\data\      模块三的卡片配置（20 张卡片 + 审计日志）
modules\opsgen\data\      模块二的自定义模板、历史、分享
modules\filelist\data\    模块四的书库配置（登记的根目录，一个小 json）

> 模块一**没有自己的 data 目录** —— 它写的是中台主库里的 `resource` 表，
> 所以 `data\` 那一条已经把它包进去了。
```

**关键：SQLite 必须连 `-wal`、`-shm` 一起拷。**
主库文件可能很小、内容还在 WAL 里，只拷 `.db` 会丢数据。

稳妥做法是先正常关停（Ctrl+C），再整体拷贝整个目录。

### 恢复

把备份的目录覆盖回去即可。若之前是强杀进程停的，先删除残留的 `-wal`/`-shm`
（它们与旧主库是配套的，混用会出错）。

### 检查点（让主库自包含）

正常关停时 SQLite 会自动合并 WAL。如果你刚强杀过进程，可以手动做一次：

```bash
.venv\Scripts\python.exe -c "import sqlite3; c=sqlite3.connect(r'data/localdeck.db'); print(c.execute('PRAGMA integrity_check').fetchone()[0]); c.execute('PRAGMA wal_checkpoint(TRUNCATE)'); c.close()"
```

输出 `ok` 且 `-wal` 归零，就说明合并成功。**合并前后业务数字（如应用条数）必须一致。**

## 六、常见问题排查

### 先看日志

中台的日志在 `data/logs/localdeck.log`（轮转：20MB × 14 个）。任何"说不清为什么"
的问题，先翻它最后几十行：

```
2026-09-18 16:53:43.118 [INFO ] localdeck: 启动中台 Personal Workspace v0.4.0｜端口 8731｜…
2026-09-18 16:53:43.763 [WARNING] localdeck.http: 401 GET /opsgen/ —— 第三方模块路径不认浏览器会话，需要令牌或模块票据
2026-09-18 16:53:44.021 [INFO ] localdeck.http: GET /api/overview -> 200  81ms
```

**401 一定带原因** —— 这是设计上就要求写清楚的一句话。常见几种：

| 日志里的话 | 真正的问题 |
|---|---|
| 没带任何凭据（请求头与会话 Cookie 都没有） | 裸访问了接口，或者浏览器会话没建起来 |
| 会话已失效（过期 / 已登出 / 令牌被重置后集体作废） | 重新登录即可：页面会自己弹登录窗 |
| 请求头里的令牌与当前令牌不符 | 用的是旧令牌（换过数据目录？删过 `data/.token`？） |
| 第三方模块路径不认浏览器会话 | 第三方模块只能用令牌或模块票据 —— 这是刻意的，不是坏了 |
| 模块票据与当前轮次不符 | 模块重启过了，从模块卡片重新进一次即可 |

日志本身**不记令牌明文、不记会话号、也不记完整 URL**（参数只记名字不记值），
所以可以放心把整段贴出来。

> 一个踩过的坑：接入 `data/logs` 之前，`uvicorn` 是按 `log_level="warning"` 起的，
> **连访问日志都没开** —— 出问题时唯一的信息来源就是浏览器里那条红条，
> 而红条只会说"失败了"，不会说"为什么"。这也是日志要落到文件、而不是只打印的原因。

### 提示端口被占用

启动时会自动探端口，并直接告诉你占用者是谁：

```
  [X] 端口 8731 已被占用 —— PID 26796（python.exe）。
      多半是已经有一个中台在跑：先关掉那个窗口。
      窗口关了但进程还在的话，结束它：
          taskkill /F /T /PID 26796
```

**`/T` 这个参数别省** —— 中台在 Windows 上是「父 + 子」两个同名进程，只杀父进程
会留下孤儿子进程继续占着端口，下次还是起不来。

自己查也是同一套：

```bash
netstat -ano | findstr :8731
taskkill /F /T /PID <PID>
```

想同时跑两个实例：`set LOCALDECK_PORT=8741` 之后再启动。

### 服务起不来 / 浏览器打不开

1. 看启动窗口有没有红字报错
2. 确认命令行窗口还开着（关掉窗口服务就停了）
3. 确认地址是 `http://127.0.0.1:8731` 而不是 `localhost`
4. 令牌失效时页面会提示「缺少访问令牌」——重新从启动窗口复制带令牌的地址

### 依赖装不上

国内网络环境下可以指定镜像源：

```bash
.venv\Scripts\python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r backend\requirements.txt
```

走代理的话先设：

```bash
set HTTPS_PROXY=http://127.0.0.1:7890
```

模块的依赖装在各自的私有环境里，装不上就单独重建那一个：

```bash
scripts\setup-modules.bat --only opsgen --force
```

**别把模块的依赖装进中台的环境**：模块是第三方代码，它钉的版本随时可能和中台的
FastAPI / uvicorn 打架，合成一个环境之后，升级模块顺手换个 Flask 版本就可能让
中台起不来 —— 而那时你根本想不到问题出在一个"不相关"的模块上。

### 扫描结果少得离谱

正常应该有几条到几百条。如果只有个位数，通常是注册表读取被拦——
以管理员身份运行 `start.bat` 再试一次。

## 八、外观自定义（改名字 / 配色 / Logo / 背景图）

页面右上角「**外观**」按钮。改动**即时预览**，点「保存」才写进配置；
没保存直接关掉会自动还原，并提示「未保存的改动已还原」。

| 想改 | 位置 | 限制 |
|---|---|---|
| 平台名称 | 品牌 → 平台名称 | ≤ 32 字 |
| 副标题 | 品牌 → 副标题 | ≤ 48 字 |
| 左上角方块里的字 | 品牌 → Logo 文字 | ≤ 4 字符，同时用作浏览器标签页图标 |
| 换成图片 Logo | 图片 → Logo 图片 | 原图 ≤ 约 620 KB，会盖住 Logo 文字 |
| 整页背景图 | 图片 → 页面背景图 | 原图 ≤ 约 1.2 MB |
| 背景上的蒙层浓度 | 图片 → 背景蒙层 | 0–90%，图越花越该调高，否则文字看不清 |
| 背景样式 | 配色 → 背景样式 | 光晕 / 网格 / 纯色 |
| 一键换主副色 | 主题预设 | 极光 / 深海 / 日落 / 森绿 / 紫罗兰 / 石墨 |
| 浅色 ↔ 深色 | 配色 → 明暗 | 见下方说明 |
| 逐个颜色微调 | 配色 → 取色器 | 主色 / 副色 / 底色 / 面板 / 文字 |

### 改坏了怎么回退

界面上：外观面板最下面「**恢复默认**」。

命令行（服务在跑着也能执行，刷一下页面就生效）：

```bash
.venv\Scripts\python.exe -c "import sqlite3; c=sqlite3.connect(r'data/localdeck.db'); c.execute(\"DELETE FROM meta WHERE key='branding'\"); c.commit(); c.close(); print('已清除品牌配置，刷新页面生效')"
```

### 几个常见疑问

**图片传不上去，说超限。**
上限是原图约 620 KB（Logo）/ 1.2 MB（背景）。图片以 data URL 存进数据库，
所以它会计入 `localdeck.db` 的体积——**备份时会一并带走，这是有意的**（见 ARCHITECTURE 第六节）。
先压缩一下再传，背景图 1920×1080 的 JPG 通常在 300 KB 以内。

**上传的图会被传到外网吗？**
不会。中台不发起任何外部请求，图片只写进本地数据库。
唯一例外是你自己在取色框里填 `http(s)://` 外链地址——那是浏览器直接去取的。

**切到深色模式时底色跟着变了？**
设计如此。切换时如果你的底色还等于该模式的默认值（说明你没动过它），会一并换成另一套默认值；
**自己调过的颜色不会被覆盖**。

**改完名字，内部的东西也变了吗？**
没有。令牌请求头 `X-LocalDeck-Token`、数据库文件名 `localdeck.db`、目录名都不随品牌改名而变。
否则已有数据和浏览器书签会一起失效。它们不出现在界面上，可以忽略。

**老浏览器上颜色不对。**
界面用到 CSS `color-mix()`，需要 Chrome / Edge 111+ 或 Firefox 113+。
更低版本不会白屏，只是配色退回一套静态兜底色。

## 九、安全自查清单

每次改完配置，过一遍这几条：

- [ ] `modules/portal/.env` 的 `SECRET_KEY` 不是默认值
- [ ] `modules/portal/.env` 的出厂管理员口令不是弱口令（**它现在挂在 8731 上了**）
- [ ] `.env` 没有被提交到版本库（已在 `.gitignore` 中）
- [ ] 中台只监听 `127.0.0.1`（`netstat -ano | findstr :8731` 看到的应是 `127.0.0.1:8731`，不是 `0.0.0.0:8731`）
- [ ] 模块的内部端口同样只绑回环（同上，查 8732 / 8733）
- [ ] **上游模块的源码没被改过** —— 自检脚本会断言那句 `host="0.0.0.0"` 仍在原位
- [ ] OpsGen 的实时通道（socket.io）仍是被阻断的（那条通道挂着任意命令执行）
- [ ] 任何执行脚本的能力都还没有对浏览器开放
- [ ] **零 Cookie 请求不能拿到模块的登录态** —— 中台代理不得在服务端替任何人记住会话。
      自检脚本里有一对判据专门盯它（先确认模块确实发出过会话，再确认零 Cookie 拿不到数据）。
      历史上有过真实越权：见「模块三」一节
- [ ] **模块三的免登录只在经中台时生效** —— 直连它的 8733 必须还是 401。
      自检脚本里有这条反向判据；免登录的正当性完全来自上游那道边界
- [ ] **模块四仍是只读的** —— 它不该有任何写/删/移/改名文件的接口，
      也不该读文件内容。越界路径（`..` / 绝对路径 / 指向根外的链接）必须一律被拒，
      自检脚本里有 6 个探针盯这件事
- [ ] **模块五的只读边界** —— 日志文件只读（不开写模式、不删不移不改名），
      可读范围限于登记的日志根目录。越界路径必须一律被拒，
      自检脚本里有 **9 个探针**盯这件事；另外它得记住"接口、网关、WebSocket
      都要走同一个判定函数"，少探一个入口就可能漏
- [ ] 跑一遍自检，五个模块全过：
      `check_modules.py --module inventory`（12 项）、`--module filelist`（18 项）、
      `--module opsgen`（34 项）、`--module logviz`（20 项）、`--module portal`（23 项）
- [ ] **改过鉴权就跑 `backend\scripts\check_auth.py --log`**（32 项）——
      它验令牌 / 浏览器会话 / 模块票据三条通道的边界。**这个不需要服务在跑**：
      模块的内部端口是模块自己写死的，本机没法再起第二个实例做"干净环境"的检查
      （第二个实例要么撞端口，要么被接管到第一个实例的进程上，拿到的票据是别人的，
      检查结果会假得像真 bug —— 实测见过 portal 报一个完全不存在的「免登录失效」）。
