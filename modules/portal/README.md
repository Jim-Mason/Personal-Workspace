# 开发工具箱（Dev Toolbox）

把常用的内网系统收进一个门户页面，**在云上跳板机部署一份，本地浏览器只访问跳板机**，
  
点一下卡片就能进到内网系统 —— 不需要在本地装 VPN、改 hosts、配代理。

- **前端**：React 18 + Vite + TypeScript（浅色卡片式工具箱界面）
- **后端**：FastAPI + SQLAlchemy 2.0（同时托管前端静态文件，单进程单端口）
- **数据库**：SQLite（单文件、零运维，备份就是拷文件）
- **认证**：账号密码 + JWT，令牌走 HttpOnly Cookie（前端 JS 拿不到）

> **这一节原本有 28 张实拍截图，没有随仓库发布。**

> 想看实际效果，跑起来即可 —— 首次启动会自动灌入一组示例卡片。

界面本身值得说的几处：

- **拖拽排序**：卡片可直接拖动调整顺序，拖完即时生效，不必进编辑页
- **卡片外观自定义**：表单里改图标 / 底色 / 强调色，右侧实时预览
- **一张卡片挂多个环境**：磁贴上显示 `N 个环境` 角标（而不是 `代理` / `直连`），
  点下去先弹环境列表，每行标明这条走**代理**还是**直连**，点「打开」才跳转
- **导入前先预演**：xlsx 导入会先列出将被影响的每一行，非法单元格按**物理行号**定位
- **导出可选格式**：导出前选格式，完成后有明确提示
- **分组一点即选**：已有分组下拉可选，也能直接写新分组名（自动出现「新建」项）

**核心能力是反向代理网关。** 浏览器地址栏是跳板机的 `/gw/<slug>/`，页面内容却来自内网目标站点；
连目标站点自己拼出的**绝对地址**（例如 Jenkins 用 `Server.getRootUrl()` 生成的
`/theme-dark/theme.css`）也会被网关收进来。这就是"本地访问不了内网，照样能打开内网页面"的做法。

## 一、为什么需要它

你本机访问不了 `192.168.x.x` / `10.x.x.x` 的内网系统，但**跳板机可以**。
  
本项目的核心不是"做个导航页"，而是后端实现了**反向代理网关**：

```
本地浏览器 ──► 跳板机 https://toolbox.xxx/gw/zentao/  ──► 内网 192.168.1.16:8080/
             （只连跳板机这一个地址）        （跳板机在 VPC 内，能直达内网）
```

所以卡片链接指向的不是内网 IP，而是**跳板机自己的路径**。内网地址只存在于
  
跳板机的数据库和配置里，从不暴露给本地浏览器。

## 二、两种打开模式

每张卡片可以单独选择，在「功能管理」里随时切换：

| 模式           | 链接指向                        | 适合场景              | 前提       |
| ------------ | --------------------------- | ----------------- | -------- |
| 代理访问 | `/gw/{slug}/`               | 本机完全访问不到内网系统      | 跳板机能访问目标 |
| **直连访问（优先）**     | 原始 `http://192.168.x.x/...` | 本机已经能访问（例如已连 VPN） | 本机能访问目标  |

代理模式下，门户还会自动做这些事，让内网页面"看起来就像原生打开"：

| 处理项               | 说明                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| HTML 根路径资源        | 注入 `<base href="/gw/{slug}/">`，并把 `src="/x"`、`href="/x"`、`action="/x"`、内联 `url(/x)` 重写到 `/gw/{slug}/x` |
| 独立 CSS 文件         | 同样重写其中的 `url(/x)`，否则背景图、字体图标会 404                                                                      |
| 重定向               | 站内 `Location: /page2` → `/gw/{slug}/page2`；跳外站则原样放行                                                    |
| Cookie            | 剥离 `Domain`（门户与目标不同域会被浏览器拒收）、`Path` 改写到网关前缀；门户是 HTTP 时自动降级 `Secure` / `SameSite=None`                  |
| 门户自身令牌            | `dtb_access` / `dtb_refresh` **绝不转发**给内网系统，避免令牌外泄                                                      |
| 安全头               | 按需剥离上游 `X-Frame-Options` / `CSP`，便于 iframe 或跨端嵌入                                                       |
| WebSocket         | `/gw/{slug}/ws` 原样透传，内网系统的实时推送页面也能用                                                                    |
| 大文件               | 非 HTML/CSS 响应**零拷贝流式透传**，保持原始 `Content-Encoding`，不做内存缓冲                                                |
| **JS 运行时拼的根路径**   | 注入客户端 shim，把 `fetch("/api/x")`、`XHR.open("/api/x")`、`new WebSocket("/ws")` 等改写成 `/gw/{slug}/api/x`     |
| **与目标同源的绝对地址**    | `href="http://内网主机:8081/theme.css"` 这类**完整 URL** 也收进网关 —— 否则浏览器会绕过网关直连内网主机，请求直接失败、样式整片丢失 |
| **shim 也漏掉的顶层导航** | 服务端按 `Referer` 兜底转发（见下）                                                                                |

> 编码问题：HTML 重写是**字节级**的，不经过任何解码/编码。
>   
> 因此老内网系统的 GBK 页面也能正常重写，不会出现乱码。

> **为什么优先直连**：代理虽然能把"本机访问不到"的系统变成可达，
> 但会把所有系统压到门户的同一个 origin 下，带来**登录凭据串填、存储键撞车**等副作用 ——
> 详见下一节。本项目当前 20 张卡片**全部使用直连**。

**打开方式既是卡片级、也是环境地址级的**：一张卡片可以挂多个地址（见「三、卡片自定义 →
一张卡片挂多个地址」），**每条地址自带自己的打开方式**。
所以同一张卡片完全可以"生产走代理、测试走直连" —— 两个环境被代理这件事绑在一起是没必要的。

### 代理不是免费的：同源会让「登录」互相串（本项目当前全部改用直连）

代理模式下，**所有**目标系统都跑在门户的同一个 origin 下（`http://门户/gw/xxx/`）。
浏览器的很多能力是**按 origin 记账**的，于是会出现几类"看起来像 bug"的现象：

| 现象 | 原因 | 代理能否解决 |
| ------------------------------ | -------------------------------------------------------- | ---------------------------- |
| 目标系统的登录框被自动填上门户的账号密码，提示**密码错误** | 浏览器的密码管理器给门户这个 origin 存了凭据；代理页同源，于是被当成"同一个站点"自动填充 | ✗ 代理管不到浏览器自动填充 |
| 两个系统同名 Cookie 互相覆盖 | 同源，Cookie 按 name + path + domain 去重 | ✓ `PROXY_COOKIE_NAMESPACE=true`（有副作用，见〈已知限制〉） |
| 两个系统 `localStorage` / `sessionStorage` 键撞车 | 同源，存储本来就按 origin 隔离 | ✗ 改不了 |
| Service Worker 作用域冲突 | 同源 | ✗ 改不了 |

**结论：只要"本机能不能访问到目标"这个前提允许，就优先用直连。**
直连时每个系统都是自己的 origin，密码记忆、Cookie、本地存储天然互不干扰，
也没有任何页面改写带来的副作用 —— 这正是本项目目前的做法（12 张卡片全部为直连）。

需要保留代理的**唯一**场景是：**本机根本访问不到目标地址**（只有跳板机通）。
那种情况下更好的做法是给网关一个**独立域名**（如 `tools-gw.example.com`），
从根上把 origin 分开；代价是要加 DNS 与证书，且网关的登录态需要另行处理。

### 目标地址的两种作用域（由是否以 `/` 结尾决定）

同样是填地址，**结尾有没有 `/`** 决定门户怎么解析页面里的链接。这不是"格式偏好"，而是语义：

| 目标地址      | 作用域       | `/gw/{slug}/x` 实际请求 | 适合                        |
| --------- | --------- | ------------------- | ------------------------- |
| `...:8081/` | **目录作用域** | `...:8081/x`        | 站点根就是入口                   |
| `...:8081/app/` | **目录作用域** | `...:8081/app/x`    | 应用装在某个上下文路径下              |
| `...:8081/login` | **页面作用域** | `...:8081/x`        | 入口是一个**具体页面**，站点根反而不可用（如 Jenkins：`/` 返回 403，`/login` 才 200） |

页面作用域还保证**入口原样打开**：`http://host/login` 与 `http://host/login/` 在不少系统里
是两个不同页面（Jenkins 就是前者 200、后者 404），所以门户不会自作主张补斜杠。

> 判断口诀：**填到目录就带 `/`，填到页面就不带。**

### 第二类容易漏的：与目标同源的绝对地址

`<base>` 管的是相对路径；shim 管的是运行时拼的根路径。还有第三类——

```html
<link rel="stylesheet" href="http://10.0.0.20:8081/theme-dark/theme.css">
```

这是**完整 URL**，语义上"不是外链"（就是目标自己），但在跳板机场景里浏览器会绕过网关直连
`10.0.0.20:8081` —— 而本机根本访问不到那个地址，请求直接失败（`status=0`），
于是页面样式整片丢失、剩下的 HTML 光秃秃。Jenkins 的主题 CSS 就是这么来的
（它用 `Server.getRootUrl()` 拼地址）。

门户的处理：**只要 host:port 与卡片目标同源**（含 `//host/x` 协议相对写法），
就按上表的作用域改写进网关；真正的外链（`example.com`、`cdn.*`）原样放行。
独立 CSS 文件里的 `url(http://同源host/...)` 同样处理。

### 最容易被漏掉的一类：JS 运行时拼出来的地址

`<base>` 只影响**相对路径**（`a/b`、`./a`）。像 `fetch("/api/v1/game-config")`
  
这种**根路径绝对地址**，浏览器会直接打到门户域名根上 —— 于是它会命中门户自己的路由，
  
收到一个 404，内网页面就"半死不活"：静态资源都好好的，唯独接口全挂。

这类地址在 JS 里**运行时**才拼出来，字节级重写根本看不到。所以分两层堵：

1. **客户端 shim（页面内，按标签页生效）** —— 注入到被代理页面的最前面，
     
   改写运行时发出的根路径请求：`fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` /
     
   `Worker` / `ServiceWorker.register` / `sendBeacon` / `window.open` / `setAttribute` /
     
   常见元素的 `src`·`href`·`action` 属性赋值。
     
   **不碰**相对路径（交给 `<base>`）与**真正的外链**；与目标同源的 `http(s)://目标host/x`
   和 `//目标host/x` 会一起改写（见下"与目标同源的绝对地址"）。
2. **服务端兜底（按 `Referer` 推断归属）** —— `location.href = "/x"` 这类顶层导航
     
   改不了（`window.location` 是 `[Unforgeable]`），因此服务端还留了一条兜底：
     
   未匹配任何门户路由的请求，如果 `Referer` 指向 `/gw/<slug>/`，就按该 slug 转发。

兜底转发有三道闸：**先过网关鉴权**（`Referer` 是客户端可控的，不鉴权等于白送内网访问）、
  
卡片必须存在且已启用且是**代理模式**、路径不能落在门户自身命名空间里
  
（`/api/cards`、`/api/auth`、`/uploads`、`/assets` … 一律不转发）。

### 卡片本身怎么打开：真实链接，不用 window.open

门户首页的磁贴、以及「功能管理」里的「预览」，都是**真实的 `<a href target="_blank" rel="noopener noreferrer">`**。
点击后由浏览器做常规导航，**不受弹窗拦截策略约束**，因此也支持中键 / `Ctrl+点击` / 右键「在新标签页打开」。

> ⚠️ **不要用 `window.open()` 的返回值判断"是否被浏览器拦截"。**
>
> 早先磁贴用的是 `<button>` + `window.open(url, '_blank', 'noopener,noreferrer')`，
> 并拿返回值 `Boolean(win)` 判断拦截。但按 HTML 规范，
> **只要 `windowFeatures` 里带 `noopener`，`window.open()` 就固定返回 `null`**，
> 哪怕新标签页已经正常打开（`noreferrer` 同样隐含 `noopener`）。
>
> 实测（Chromium）：点一次这种调用，标签页从 1 个变成 2 个 —— 页面确实开了，
> 而记录到的返回值是 `null`。于是每次点击都弹出
> 「浏览器拦截了新标签页，请允许本站弹出窗口后重试」——**提示在说谎**，
> 用户按提示去放开弹窗权限也不会有任何变化。
>
> 所以：要新标签页就用 `<a target="_blank">`；确实需要 `window.open` 时，
> 不要传 `noopener`，改为开完就 `win.opener = null`，这样返回值才真实。
> 仓库里 `backend/scripts/check_launcher.mjs` 会扫描源码阻止这个坑被改回来。

| 打开方式 | 弹窗拦截策略 | 能否拿到返回值判断拦截 | 中键 / Ctrl+点击 |
| -------- | ---------- | ------------------ | -------------- |
| `<a target="_blank">`（本项目采用） | 不适用（用户主动导航） | 不需要 | ✅ |
| `window.open(url,'_blank')` | 适用 | ✅ 可判断 | ❌ |
| `window.open(url,'_blank','noopener')` | 适用 | ❌ **恒为 `null`** | ❌ |

## 三、卡片自定义

门户首页和「功能管理」都能改卡片，管理员**在首页就能完成**，不必跳进管理页。

| 能力      | 入口                               | 说明                                                       |
| ------- | -------------------------------- | -------------------------------------------------------- |
| 卡片上直接改  | 首页**悬停卡片** → 右上角出现「✎ 编辑 / 🗑 删除」 | 编辑直接弹表单，删除有二次确认                                          |
| 自定义图标   | 表单 →「图标与外观」→ 上传图片                | PNG / JPG / WEBP / GIF / ICO / BMP，≤512KB；也支持 http(s) 外链 |
| 卡片外观    | 表单 →「图标与外观」                      | 8 种底色预设 + 字符图标配色 + 图标主色（主色可用取色器自定义）                      |
| 拖拽排序    | 首页右上角「调整顺序」→ 拖动卡片 →「完成」          | 松手即自动保存，刷新后顺序保持                                          |
| 分组选择    | 表单 →「分组」                        | 已有分组**一点即选**（输入框下方平铺全部候选，下拉可搜索）；也能直接输入新分组，保存后自动进入候选         |
| 多环境地址   | 表单 →「环境地址（可选）」                   | 一张卡片挂**最多 20 条**地址（生产 / 测试 / 灰度…），**每条独立选直连或代理**；点卡片先弹列表挑一个再跳         |
| 导入 / 导出 | 「功能管理」右上角「导出配置 / 导入配置」           | 导出可选 **Excel / CSV / JSON** 三种格式；导入支持上传这三种文件，且**先预演**影响面          |

表单顶部有**实时预览**，改底色 / 主色 / 图标能立刻看到效果，不用先保存再回首页确认。

### 一张卡片挂多个地址（环境归档）

同一个系统往往有 **生产 / 测试 / 灰度 / 本地** 好几个入口。以前的做法是给每个环境建一张卡片，
结果门户首页被同一个系统的四张卡占满 —— 归档起来很难受。

现在**一张卡片可以挂多条地址**：表单里选好图标和名称，再往下把各环境地址一条条列进去。

| 你在表单里填的                       | 门户上的表现                                    |
| ----------------------------- | ----------------------------------------- |
| 「环境地址」区里加行：`生产` / `http://10.0.0.5:8080/` / `代理` | 磁贴右下角变成 `2 个环境` 角标，而不是 `代理` / `直连` 徽标      |
| 再加一行：`测试` / `http://10.0.0.6:8080/` / `直连`        | 点这张卡片**不会直接跳转**，而是先弹出环境列表                |
| 用 `↑` `↓` 调顺序                      | 列表里就按这个顺序显示，第 1 条同时也是鼠标悬停的提示文字           |

弹出来的列表长这样 —— 标题就是卡片名，每行是「名称 / 地址 / 模式 / 打开」，
**点「打开」才真的跳**：

```
┌──────────────────────────────────────────────┐
│ 地址导航                               [×] │
│ 这张卡片有 2 个环境地址，选一个打开。                   │
├──────────────────────────────────────────────┤
│ 生产   http://10.0.0.5:8080/   [代理]   [打开]      │
│ 测试   http://10.0.0.6:8080/   [直连]   [打开]      │
├──────────────────────────────────────────────┤
│ 提示：需要新标签页打开可以勾选表单里的「在新标签页打开」。     │
│ 这一层列表会拦掉中键与右键，是"先确认环境"的代价。           │
└──────────────────────────────────────────────┘
```

#### 为什么先弹列表，而不是"点卡片直接进第一个"

因为**点错环境的代价不对等**：多一次点击只是麻烦一下，点错进生产是多一次事故。
多出来的这一次点击，换来的是"跳之前你确知自己要跳哪个环境"。

> **代价要说清楚**：因为跳转动作变成了列表里的一个按钮，
> 浏览器原生的「中键点击 / Ctrl+点击在新标签页打开」就失效了
> （浏览器只对真实链接做这个，对按钮不做）。
> 如果你更需要中键开新页，那就把这张卡片的**环境地址留空** ——
> 单地址卡片仍然是 `<a target="_blank">`，中键、Ctrl+点击、右键"在新标签页打开"全都正常。

#### 每条地址自己决定走不走网关

「环境地址」每行末尾有个 `代理 / 直连` 下拉 —— **它是这条地址自己的属性**，跟卡片上的
「访问方式」是两回事：

- 卡片上的「访问方式」= 这张卡片**没有环境地址时**用什么方式打开；
- 每行的 `代理 / 直连` = 这个**具体环境**走不走跳板机。

所以可以配成「生产走代理（本机到不了生产网段）、测试走直连（本机连得上测试环境）」。
网关那边对此**零改动**：每条环境地址在入库时也会分到一个**独立入口标识** ——
`{卡片标识}-{环境名转成的 slug}`（环境名是纯中文转不出 slug 时，回落成 `{卡片标识}-{序号}`）——
它就是这条地址的专属网关入口 `/gw/xxxx/`，
转发、HTML 重写、Cookie 处理、TLS 校验全部沿用同一套逻辑。

#### 环境地址的入口标识会被"认领"，所以书签不会失效

保存时按**入口标识**（而不是按地址）比对：同一条地址改个名字，它的入口标识不变；
地址改名换了标识，就是新增一条。这意味着 ——
**一条环境地址只要还在，它 `/gw/xxx/` 形式的链接就一直有效**，同事存的书签不会因为
你调整了列表顺序或改了另一条地址而失效。

> 环境地址的**点击量记在卡片上**（而不是记在每条地址上），
> 但审计日志里会写明点的是哪一个环境的标识 —— 所以"这个卡片有多少人用"和"哪个环境被点得多"都能查。

### 导出：三种格式，一份列定义

点「导出配置」是**下拉菜单**，三种格式任选：

| 格式               | 适合谁用它                              | 特点                                                                     |
| ---------------- | ---------------------------------- | ---------------------------------------------------------------------- |
| **Excel（`.xlsx`）** | 想用 Excel 批量改卡片的人（推荐）               | 带**表头样式 + 列批注 + 枚举列下拉校验**，另附一页「字段说明」；Excel 里改完直接导回                 |
| **CSV（`.csv`）**   | 想用脚本 / `sed` / 数据库工具批量处理            | 纯文本最通用；**带 UTF-8 BOM**，双击用 Excel 打开也不会中文乱码                             |
| **JSON（`.json`）**  | 程序化对接、进 Git 做版本管理、看完整结构            | 保留 `version` / `exported_at` / `count` 等元信息，结构最完整                       |

三种格式的列顺序、列名、取值含义**只有一份来源** —— 后端 `card_sheet.CARD_COLUMNS`。
导出用它，导入也用它解析，所以 **"导出 → 在 Excel 里改 → 再导回"是闭合的**：
不会出现"导出的列名导不回去"这种事。

文件名形如 `dev-toolbox-cards-20260916-173327.xlsx`（带时间戳，多次导出不会互相覆盖），
卡片数量走 `X-Card-Count` 响应头返回，因此提示语里的"已导出 12 张卡片"不用去解析文件内容。

### 导出的 JSON 结构

只含"可迁移"的配置 —— 不含 `id`、点击量、时间戳，所以换台机器也能直接用：

```json
{
  "version": 1,
  "app": "dev-toolbox",
  "exported_at": "2026-09-16T01:26:01",
  "count": 9,
  "cards": [
    {
      "slug": "address-nav",
      "title": "地址导航",
      "description": "集中查看原型与内部系统入口。",
      "icon": "址",
      "icon_style": "blue",
      "icon_url": "",
      "bg_style": "",
      "accent_color": "",
      "target_url": "http://192.168.1.10:8080/",
      "open_mode": "proxy",
      "group_name": "常用工具",
      "sort_order": 10,
      "enabled": true,
      "open_in_new_tab": true,
      "verify_tls": null,
      "endpoints": [
        {
          "name": "生产",
          "url": "http://10.0.0.5:8080/",
          "open_mode": "proxy",
          "verify_tls": null,
          "slug": "address-nav-1"
        },
        {
          "name": "测试",
          "url": "http://10.0.0.6:8080/",
          "open_mode": "direct",
          "verify_tls": null,
          "slug": "address-nav-2"
        }
      ]
    }
  ]
}
```

`endpoints` 是**可选**字段（没挂环境地址的卡片导出时是 `[]`）。
字段名与卡片级同名（`open_mode` / `verify_tls`），但作用域是**这一条地址自己**：

| 字段         | 含义                                                       |
| ---------- | -------------------------------------------------------- |
| `name`     | 环境名（生产 / 测试 / UAT…）。**同一张卡片里不能重名**（大小写不敏感），最多 20 条        |
| `url`      | 该环境的地址，必须带 `http://` 或 `https://`，同样过 SSRF 黑名单             |
| `open_mode` | 这条地址怎么打开：`direct`（默认）或 `proxy`                            |
| `verify_tls` | 三态：**省略 / null** = 跟随全局；`true` = 强制校验；`false` = 强制不校验      |
| `slug`     | 这条地址的网关入口标识。**导出会带上、导入会复用** —— 所以在两台机器之间刷配置，旧书签不会被改掉 |

> `slug` 是**导入时优先复用**而不是"必须"：库里已有同名标识就沿用，没有才按
> `{卡片标识}-{序号}` 新生成。因此「导出 → 导入到另一台 → 再导回」不会把链接刷乱。

### 导入的两种模式

| 模式         | 行为                                  | 适合场景            |
| ---------- | ----------------------------------- | --------------- |
| **合并（推荐）** | 按 `slug` 匹配：命中则更新，未命中则新建；库里其他卡片不受影响 | 增量同步、同事之间共享卡片配置 |
| **覆盖全部**   | 先清空当前所有卡片，再按导入内容重建                  | 整机还原、换环境迁移      |

选好文件后会**先做一次预演**（服务端 `dry_run`），把"新建 / 更新 / 删除 / 跳过"的数量摆出来，
  
确认后才真正写库。单条数据非法（缺 title、地址协议不对、命中 SSRF 黑名单等）只跳过该条，
  
并在弹窗里逐条列出原因，不会让整批导入失败。

> 上传的图标落在 `data/uploads/icons/`，文件名由服务端生成（uuid + 白名单扩展名）。
>   
> 卡片**保存后**才会引用它；如果上传完直接关掉弹窗，那个文件会留在磁盘上（见〈已知限制〉）。
>
> **图标读取需要登录**：`/uploads/icons/<uuid>.png` 走的是带鉴权依赖的显式路由
>   
> （不是 `StaticFiles` 挂载 —— 静态挂载挂不上鉴权，会让图标变成"知道文件名就能看"的公网资源）。
>   
> 未登录访问返回 401，与其他业务接口策略一致；因此图标缓存也用了 `private` 而不是 `public`。

### 导入支持哪些文件

导入框接受 `.xlsx` / `.xlsm` / `.csv` / `.json`，**按文件内容判断格式，扩展名只作兜底**
（`.xlsx` 是 zip，开头 `PK\x03\x04`；`.xls` 是 OLE2，开头 `\xd0\xcf\x11\xe0`）。
所以文件被微信 / 邮件改名了也照样能认出来。

| 文件        | 说明                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------- |
| `.xlsx`   | 从门户导出的那份（推荐）。工作簿里有多个表时，自动挑**"表头能认出 ≥3 列"**的那个                                                   |
| `.csv`    | 编码依次按 UTF-16(BOM) → UTF-8(BOM) → GB18030 尝试，**GBK 的旧表格不会乱码**；分隔符自动嗅探（`,` / `;` / Tab / `\|`） |
| `.json`   | 门户导出的 JSON，或手写的 `{"cards": [...]}` / 纯数组                                                       |
| `.xls`    | **不支持**。会提示先用 Excel「另存为」`.xlsx` 或 `.csv` 再来                                                   |
| 二进制垃圾文件  | 提示"这个文件是二进制内容，不是卡片表格"，而不是含糊地报"没找到卡片列"                                                      |

### 表格里的几个约定

- **表头怎么认**：在**前 10 行**里挑"能认出列最多"的那一行当表头 —— 所以上面多一行大标题、或多空几行都不影响。
  列名**中英文都认**（`名称` = `title`），并兼容常见别称；大小写、空格、下划线、连字符会归一化后比较。
- **留空的格子 = 用默认值**，不是"把这个字段清空"。
  ⚠️ 但要知道这是**整行覆盖**：某行只要有值，这一行的**所有列**就都以表格为准 ——
  比如某行只填了名称，那这张卡片的描述会变成空。
  想保留原值，就把原值一起导出来改（这也正是"导出一份 → 改完 → 导回"最稳的原因）。
- **枚举列带下拉**：`打开方式` / `图标配色` / `卡片底色` 在 Excel 里是下拉选项。
  填了规范外的值会在**导入前**就被拦下，提示是中文的 ——
  `打开方式的值「随便」无法识别（可填 直连/代理、direct/proxy），本行已跳过`，
  不会漏到后端变成一句英文的 Pydantic 报错。
- **布尔列很宽容**：`是/否`、`true/false`、`1/0`、`y/n`、`启用/停用` 都认。
- **`校验HTTPS证书` 是三态**：留空 = 跟随全局 `PROXY_VERIFY_TLS`；`是` = 强制校验；`否` = 强制不校验。
- **「环境地址」列一格写多个**：格式是 `名称 | 地址 | 模式`，多条之间用**换行**隔开（在 Excel 里
  按 `Alt+Enter` 换行，该列已设为**自动换行 + 顶端对齐**）。模式可以省略，省略就继承同一行
  「打开方式」列的值；全角竖线 `｜` 也认。例如：

  ```
  生产 | http://10.0.0.5:8080/ | 代理
  测试 | http://10.0.0.6:8080/ | 直连
  ```

  CSV 里因为**一行就是一条记录**，改用**分号**分隔多条（`;`），别用换行 ——
  用换行会把一条记录拆成两行，读回来就错位了。导出的 CSV 也是按分号写的，所以来回改是闭合的。
- **环境地址这一列"在不在"很关键**（它决定库里已有的地址是被保留还是被清空）：

  | 表格里「环境地址」列的状态      | 导入后该卡片的环境地址           |
  | ------------------- | --------------------- |
  | **整列都没有**（老表格、手写表里没这列） | 保留库里原有的，不动            |
  | 有这一列，但**某个格子是空的**    | 这个格子的卡片 **清空**全部环境地址  |
  | 有这一列，格子里写了内容        | 按内容**整体替换**这张卡片的地址列表 |

  所以"只想改描述、别动我配好的环境地址"是安全的 ——
  用老格式（没有这一列）导入就不会碰到它们。
- **非法单元格只废这一行**，其他行照常导入；被跳过的行会在预览弹窗里**按物理行号**列出
  （`第 3 行：...` 就是你 Excel 左侧看到的行号），照着改完再传一次。
  若整个文件一行都没解析出来，会**直接报错且不动数据库**，不会把现有卡片清空。

> **Excel 的两个坑，后端已经替你填了**：
>
> 1. 单元格填 `http://10.0.0.20:8081/login`，Excel 可能把它**自动认成超链接**。
>    门户写 xlsx 时把这些列强制为**文本格式**，读回来也按文本处理。
>    你手动新增行时如果发现地址被改了，把该列格式设成「文本」再填。
> 2. 名称以 `=` 开头（例如 `=SUM(A1:A2)`）会被 Excel 当**公式**，保存后读回只剩计算结果或空值。
>    门户在写单元格时显式把这类值的 `data_type` 改成文本，避免"导出的卡片导不回来"。

## 六、部署到跳板机

构建机（有 Node 环境）上先出前端产物，再整包同步到跳板机 —— **跳板机不需要 Node**：

```bash
# === 构建机 ===
./deploy/build.sh                    # 装 .venv + 编译 frontend/dist

# === 同步到跳板机 ===
rsync -av --exclude '.venv' --exclude 'node_modules' --exclude 'data' \
      ./ dev@jump-host:/opt/dev-toolbox/

# === 跳板机 ===
cd /opt/dev-toolbox
cp .env.example .env
openssl rand -hex 32                 # 把输出填到 .env 的 SECRET_KEY
vi .env                              # 至少改：ENV=prod、SECRET_KEY、BOOTSTRAP_ADMIN_PASSWORD

python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
./deploy/start.sh                    # 前台试跑，确认能起来

# 用 systemd 常驻（可选）
sudo cp deploy/dev-toolbox.service /etc/systemd/system/
sudo vi /etc/systemd/system/dev-toolbox.service   # 改 User / WorkingDirectory
sudo systemctl daemon-reload && sudo systemctl enable --now dev-toolbox
sudo journalctl -u dev-toolbox -f
```

需要 HTTPS / 独立域名时，前面再加一层 nginx，参考 `deploy/nginx.conf.example`
  
（里面已包含 WebSocket 升级头、`proxy_buffering off`、放大上传体积等必要项）。

**登录后第一件事**：打开「功能管理」，把 9 张示例卡片的 `192.168.1.x` 换成你真实的内网地址。

## 七、关键配置项

完整清单见 `.env.example`，以下是最容易踩坑的几项：

| 变量                            | 默认       | 说明                                                                         |
| ----------------------------- | -------- | -------------------------------------------------------------------------- |
| `SECRET_KEY`                  | 空        | **生产必填**，否则启动直接失败。`openssl rand -hex 32`                                   |
| `ENV`                         | `dev`    | 设 `prod` 会关闭 `/api/docs`，并强制要求 `SECRET_KEY`                                |
| `COOKIE_SECURE`               | `false`  | 门户走 HTTPS 时必须改 `true`，否则登录 Cookie 被浏览器丢弃                                   |
| `PROXY_ALLOW_PRIVATE_TARGETS` | `true`   | **跳板机场景必须保持 true**，否则代理不到 `10./172./192.168.` 地址                           |
| `PROXY_ALLOWED_HOSTS`         | 空        | 可选白名单（支持 `*.example.com`），非空时只允许代理到这些主机                                    |
| `PROXY_VERIFY_TLS`            | `false`  | 内网自签证书保持 false；也可在单张卡片上单独开启                                                |
| `PROXY_REWRITE_HTML`          | `true`   | 关闭则不做 HTML/CSS 重写，内网页面样式可能加载不出来                                            |
| `PROXY_COOKIE_NAMESPACE`      | `false`  | 多个内网系统共用 `JSESSIONID` 导致互相顶掉时可开启（会给 Cookie 加 `gw_{slug}__` 前缀）             |
| `PROXY_TRUST_ENV`             | `false`  | **保持 false**，否则机器上的 `HTTP_PROXY` 环境变量会劫持内网请求                               |
| `UPLOADS_ENABLED`             | `true`   | 关掉后「上传图片」按钮会返回 403，卡片仍可用字符图标                                               |
| `UPLOAD_MAX_ICON_BYTES`       | `524288` | 单张图标上限（512KB）。图标本来就很小，调大没有意义                                               |
| `UPLOAD_MAX_IMPORT_BYTES`     | `5242880` | 导入文件上限（5MB）。xlsx/csv 是整批配置，和图标不是一个量级；超过会返回 413                             |
| `UPLOADS_DIR`                 | 空        | 上传根目录，留空用 `<项目根>/data/uploads`。**systemd 部署时该目录必须在 `ReadWritePaths` 白名单里** |
| `ROOT_PATH`                   | 空        | 门户挂在子路径（如 `/toolbox`）时填写，网关前缀会跟着调整                                         |

## 八、安全设计

| 项       | 做法                                                                                                                                                                                                  |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 令牌存储    | Access / Refresh 均为 **HttpOnly + SameSite=Lax Cookie**，前端 JS 无法读取；不落 localStorage，不进 URL                                                                                                            |
| 令牌有效期   | Access 60 分钟、Refresh 7 天；`/api/auth/refresh` 静默续期，前端无感                                                                                                                                              |
| 密码      | PBKDF2-HMAC-SHA256，260,000 次迭代 + 随机盐；参数升级后登录时自动重哈希                                                                                                                                                  |
| 暴力破解    | 同一用户名连续失败 5 次锁定 5 分钟，并记入审计日志                                                                                                                                                                        |
| 权限      | 内置 `admin` / `user` 两种角色；卡片与用户管理仅管理员可用；系统强制保留至少一个启用管理员                                                                                                                                              |
| SSRF 防护 | 只允许 http/https；**永久禁止**云元数据地址（`169.254.169.254`、`100.100.100.200`、`fd00:ec2::254`）与链路本地/组播网段；不允许 URL 里带用户名密码；支持主机白名单                                                                                |
| 网关鉴权    | `/gw/*` 全部需要登录，未登录返回 401，不会向公网暴露内网地址                                                                                                                                                                |
| 令牌不外泄   | 转发给内网系统前剥离 `dtb_access` / `dtb_refresh`                                                                                                                                                             |
| 日志      | 结构化 JSON + 请求 ID 贯穿全链路；密码/令牌字段自动脱敏为 `***`                                                                                                                                                           |
| 错误      | 客户端只看到 `{"error":{"code","message","request_id"}}`，不返回堆栈或内部细节                                                                                                                                       |
| 图标上传    | **只按文件头（魔法字节）判定类型**，不信任客户端的 `filename` / `Content-Type`；**拒绝 SVG**（XML 可内嵌脚本，直接访问会形成同源 XSS）；文件名由服务端用 uuid 生成，杜绝路径穿越与覆盖；先写 `.part` 再改名，避免读到半截文件                                                      |
| 图标读取权限  | `/uploads/icons/*` 使用显式路由 + 登录依赖，**未登录返回 401**；不用 `StaticFiles` 挂载，因为静态挂载无法叠加鉴权，会绕过登录直接暴露文件                                                                                                         |
| 上传目录响应头 | `/uploads/*` 统一加 `X-Content-Type-Options: nosniff` + `Content-Security-Policy: default-src 'none'; sandbox` + `Cross-Origin-Resource-Policy: same-origin` + 一年 `immutable` 缓存（`private`，登录资源不进共享缓存） |
| 导入校验    | 导入的每条数据都走与手工建卡完全相同的 Pydantic 校验 + SSRF 检查，命中即跳过该条并回报原因，不会绕过安全规则                                                                                                                                     |
| 兜底转发    | 未匹配门户路由的请求只有在 `Referer` 指向 `/gw/<slug>/` **且已通过网关鉴权**时才会被转发。`Referer` 是客户端可控的，所以鉴权必须在最前；没有这道校验，任何人伪造一个 Referer 就能白嫖内网访问                                                                             |
| 兜底转发范围  | 卡片必须存在、已启用、且为代理模式；路径落在门户命名空间（`/api/auth`、`/api/cards`、`/api/users`、`/api/uploads`、`/uploads`、`/assets` …）内一律不转发。注意整个 `/api` 不能一刀切排除 —— 内网系统用 `/api/v1/xxx` 很常见                                      |
| 审计      | 登录、登录失败、改密、卡片增删改、打开卡片、图标上传、配置导入均落库到 `audit_logs`                                                                                                                                                    |

## 十一、常见排查

先在「功能管理」点这张卡片的 **自检** 按钮 —— 它会在跳板机本地发起一次探测，
  
直接告诉你"是配置问题还是网络问题"：

| 自检结果            | 含义                             | 下一步                                                                                                                                                                               |
| --------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TCP 连接失败`      | 端口没人监听，或被安全组/防火墙拦了             | 在跳板机 `curl -v` 复测；检查安全组入方向规则                                                                                                                                                      |
| `连接超时`          | SYN 被丢弃                        | 查中间网络 ACL / 防火墙策略                                                                                                                                                                 |
| `无法解析目标主机`      | DNS 不通                         | 改用 IP，或在跳板机 `/etc/hosts` 加解析                                                                                                                                                      |
| 可达但页面样式错乱       | HTML/CSS 重写没覆盖到                | 确认 `PROXY_REWRITE_HTML=true`；用浏览器 F12 看 404 的资源路径                                                                                                                                 |
| 样式整片丢失，F12 里有 `status=0` 的请求 | 页面引用了**与目标同源的绝对地址**（`http://内网主机/x`），浏览器绕过网关直连内网主机 | 本仓库已支持改写这类地址；若仍出现，用 F12 确认那条 URL 的 host 与卡片目标**是否真的同源**（端口/协议不一致就不会改写） |
| 入口页 404 / 静态资源全 404 | 目标地址填到了**具体页面**但带了 `/`，或该带 `/` 的目录没带 | 对照上文「目标地址的两种作用域」：填目录带 `/`，填页面不带 `/` |
| 可达但**某个接口** 404 | 页面用 JS 拼了根路径接口，且 shim / 兜底都没接住 | 看 F12 里那条请求的 URL：<br />· 打到**门户根**（`/api/v1/xxx`）→ 兜底没生效，检查请求有没有带 `Referer`（目标站若设了 `no-referrer` 就会这样），或切直连模式<br />· 打到**网关下**（`/gw/xxx/api/v1/xxx`）却 404 → 是内网系统自己的问题，网关已经把请求送到了 |
| 登录状态老是掉         | 两个系统的同名 Cookie 互相覆盖            | 开启 `PROXY_COOKIE_NAMESPACE=true`                                                                                                                                                  |
| 代理页面里调不了门户接口    | 客户端 shim 把 `/api/...` 也加上了网关前缀 | 这是刻意设计；需要操作门户时在新标签页打开                                                                                                                                                             |
| 点击卡片弹「浏览器拦截了新标签页」 | 旧版误报：`window.open(..., 'noopener')` 按规范**恒返回 `null`**，被当成了"被拦截"（页面其实已经打开） | 本仓库已改为 `<a target="_blank">`，不存在这个问题。若仍出现，说明前端不是最新构建 —— 重新 `npm run build` 并刷新缓存 |
| 导入提示「表格里只有表头，没有数据行」 | 表头认出来了，但一行数据都没有 | 在表头**下面**补数据行；确认数据没被写到标题行那一行里 |
| 导入后某张卡片的描述 / 分组变空了 | 表格是**整行覆盖**语义：这一行有值，则这一行的所有列都以表格为准，空格子取默认值 | 先「导出配置」拿到原值，在导出的文件上改，再导回；不要只填一列就传 |
| 导入 xlsx 后地址被改了 | Excel 把 `http://...` 改写成了超链接或日期 | 把该列格式设为「文本」再填。门户导出的文件已强制为文本格式，从导出文件改最稳 |
| 上传 `.xls` 报「不支持旧版 .xls 格式」 | `.xls` 是 OLE2 老格式，不在支持范围 | 用 Excel 打开后「另存为」`.xlsx` 或 `.csv` 再导入 |

## 十二、已知限制

这些是设计边界，不是 bug。挑常见的说清楚，免得你在生产上撞到才发现：

- **Worker / Service Worker 内部**发出的根路径请求拦不到（只改到了注册地址）；
  相对的 `fetch("x")` 没问题，因为 worker 脚本本身就在 `/gw/{slug}/` 下。
- **非 ASCII 页面（GBK 等）下不做绝对地址改写**：只重写根路径。
  这类页面要提前确认它自己是不是也用绝对 URL 引资源（Jenkins 这类 Java 站常见），
  如果是，只能改直连模式或让目标站改配置。
- 目标站设了 `Referrer-Policy: no-referrer` 时，服务端兜底拿不到 `Referer`，
  `location.href = "/x"` 这类顶层导航会退回 404。
- `history.pushState(null, "", "/x")` 改地址栏不会被拦，之后**刷新**会打到门户根。
- 只重写 HTML/CSS，不处理 `srcset`、`@import`，**不改 JS 内容**（运行时交给 shim）。
- 代理页面里调不了门户自身接口（shim 把 `/api/...` 也前缀了）——刻意的。
- 代理**不是 WAF**：只做转发与路径重写，不做内容检查、不做越权判断。
- **上传后未保存的图标会成为孤儿文件**（几十 KB 量级），需要清理时按引用关系删。
- 常见编码 / 内网证书：目标用自签 HTTPS 时默认不校验证书，**可按卡片、也可按环境地址**单独开启校验。
- **挂了环境地址的卡片，中键 / Ctrl+点击在新标签页打开失效** —— 点击被拦截去弹环境列表了。
  需要这个能力就把该卡片的环境地址留空（单地址卡片不受影响）。
- **环境地址最多 20 条 / 张卡片**，且同一张卡片内环境名不能重复（大小写不敏感）。
  上限是为了防止一个"卡片"退化成一个无限长的地址清单 —— 超过就该拆卡片了。
- **环境地址的点击量记在卡片上**，不单独统计每条地址。想知道哪个环境被点得多，
  去审计日志里按 `endpoint=` 过滤（日志里记了每次点是哪个环境标识）。

## 十三、开发约定

- **分层**：控制器只解析请求/格式化响应，业务规则在 `services/`，数据访问在 `repositories/`。
    
  控制器不写业务逻辑，服务层不依赖 FastAPI 的 Request/Response。
- **配置**：全部来自环境变量，启动时集中校验并快速失败；密钥只出现在 `.env`，绝不硬编码。
- **错误**：抛 `AppError` 子类，由全局处理器统一转成规范错误体；不向上抛裸异常。
- **迁移**：改表结构要**新增** `NNNN_xxx.sql`，不要改历史文件（执行器会校验 checksum 并拒绝启动）。
    
  回滚：`python -m app.db.migrate --down 1`（需要同名 `.down.sql`）。
- **事务**：仓储层只 `flush` 不 `commit`，事务边界统一由服务层控制。
